## Product direction that must be preserved

1. ePaperclip is the UI/product for papercliped-engine, the Proxmox-native system. The separate original papercliped repository is not interchangeable with this engine.
2. First priority is stable, usable ePaperclip: onboarding, agents, organization controls, integrations, permissions, and consistent UI. Paperclip Connect and marketing come afterward.
3. Native Paperclip is the behavioral reference, while retaining ePaperclip's current design tokens, components, layout language, and branding.
4. Connectors is the hub. Agent models/providers and plugins remain distinct. Cloudflare and similar machine-wide services belong in device plugins; organization tools belong to their organization.
5. Initial organization apps: GitHub, Discord, Slack, Notion, Vercel. Other organization providers can come in v2. Community/custom plugin extensibility is required.
6. Prefer provider sign-in/setup pages over making users assemble environment variables. Follow the actual supported provider flow; Discord bot setup still legitimately needs bot credentials.
7. Use provider marks for known providers. Do not replace them with arbitrary generic icons.
8. Agents use connected tools through native permission/grant/approval enforcement. Pin operates on the host, is not charged against organization container resources, and needs governed control rather than only read visibility.
9. Future Paperclip Connect address: <device>.connect.papercliped.co, serving the console at / and MCP at /mcp. Device owns authentication, consent, Proxmox authority, credentials, permissions, and audit. Hosted Connect manages addresses/tunnels/subscription, not device authority.
10. Do not infer a stable release number from old chat references to r25/r28. No new tag was chosen or created here.
